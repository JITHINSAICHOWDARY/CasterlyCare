CASTERLYCARE — PHASE 2.7.7 ACCEPTANCE

Patient appointment change UX
- Upcoming appointments expose Reschedule and Cancel actions.
- Reschedule preserves visit category/service and edits only date/time.
- Date/time validation prevents past slots.
- Cancellation requires explicit confirmation.
- Cancelled records remain visible in Past history.
- Action busy states prevent duplicate submissions.
- Conflict/update failures preserve the current booking until the server confirms a change.

Backend contract note
- Frontend service methods use PATCH /patient/appointments/:id/reschedule and PATCH /patient/appointments/:id/cancel.
- Existing backend reference currently exposes doctor reschedule but does not yet expose these patient-role mutation endpoints; those server routes must be added to make these patient controls live.
