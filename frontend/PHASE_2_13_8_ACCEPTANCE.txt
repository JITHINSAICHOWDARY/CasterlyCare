CasterlyCare — Phase 2.13.8 Acceptance
====================================

Realtime frontend connection resilience hardening complete.

- Browser online/offline transitions are reflected in realtime state.
- Socket reconnect attempts expose deterministic status/attempt metadata.
- Active chat threads are rejoined after reconnect through the shared realtime provider.
- Dashboard shell surfaces connection degradation without blocking secure REST actions.
- Existing REST fallback behavior remains authoritative for clinical data and chat delivery.
- No page creates a second realtime transport.

Known integration requirement: backend Socket.IO availability and server-side event emission remain external prerequisites.
